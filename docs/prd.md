# 需求文档

## 1. 应用概述

### 1.1 应用名称
成都自由人FC 球队管家小程序

### 1.2 应用描述
本次更新在既有活动管理、分队管理、MVP榜统计、战术下发闭环、群相册、装备系统与球员能力评分体系基础上，重点进行以下迭代优化：移除活动报名的候补机制（满员即停止报名）；修复报名页面自适应与滚动布局，消除双滚动条并实现底部操作栏滑动隐藏；恢复评分中心球员评分排名展示；保持退费公告、图床存储用量单位与FIFA技能点消耗等机制稳定运行。

## 2. 用户与使用场景

### 2.1 目标用户
- **队长/管理员**：发起与管理活动；配置图床服务与监控存储用量；执行结算与战术下发；管理群相册与球队数据。
- **普通队员/球员**：查看活动公告与报名（支持满员状态判定）；查看球员评分及排名榜单；通过能力点升级属性与FIFA特性技能；购买与原价出售装备；参与群相册互动与战术反馈。

### 2.2 核心使用场景
- **活动报名与规则查阅**：队员进入活动详情与报名页，查看退费规则公告；在未满员时完成报名，满员时直接显示已满员且无法继续报名；浏览页面时享受单层流畅滚动体验。
- **球员评分与排名查阅**：队员进入评分中心，查看所有球员评分列表及对应的评分排名情况。
- **图床监控与装备管理**：队长监控准确单位的图床存储；球员进行装备购买与原价出售。
- **特性与技能升级**：球员消耗能力点解锁升级FIFA特性与技能。

### 3.2 功能说明

#### 3.2.1 活动详情与报名模块
- **统一公告文案展示**：活动详情页顶部与报名区域，固定展示统一规则公告文案：「1. 请大家提前确认好时间，到场后统一缴纳场地费用，开赛4小时前退出接龙可免分摊费用，不足4小时取消仍需正常AA，可自行寻找替补顶替；2. 尽量提前10分钟到场热身熟悉队友；3. 完成报名即代表自愿遵守微信群所有公告约定。」
- **取消候补机制**：全面移除 waiting list（候补）机制。活动设定人数上限，报名人数达到上限后，报名状态直接变更为「已满员」，不可继续提交报名，不再生成候补排队列表。
- **页面布局与滚动交互修复**：
  - 适配各种手机屏幕宽度，消除横向与异常纵向溢出。
  - 移除原有的内外双嵌套滚动条结构，整个报名列表作为主体单层平滑滚动。
  - 报名操作按钮固定悬浮在页面底部；当用户向下或向上滑动浏览列表时，底部操作按钮自动隐藏/收起，停止滑动或停留在顶部/底部时正常呼出，确保内容可视区域最大化且交互整洁。

#### 3.2.2 评分中心页（/pages/rating）
- **评分列表展示**：展示全队球员的综合评分与详细表现数据。
- **评分排名恢复与展示**：在球员评分列表项中恢复展示「评分排名」（如第1名、第2名等序列名次），支持按球员综合评分从高到低进行排序与序号标记。

#### 3.2.3 图床设置页（/pages/picui-settings）
- **单位换算与展示修正**：对 picui.cn /profile 接口返回的数据进行准确换算解析：已用存储量（size 字段）原始值为 KB，前端标注并以 KB 为单位展示（或换算为 MB/GB 并保留两位小数）；总存储容量（capacity 字段）按标准容量单位（如 10GB）展示。
- **账号信息看板**：展示用户名、总容量、已用容量及图片总数。

#### 3.2.4 装备系统（商城与背包）
- **装备类型与购买**：支持多种分类装备展示与购买，消耗积分/金币购买后进入背包。
- **装备原价出售（回收）**：在背包中提供「原价出售」功能，系统100%全额返还购买金额并回收装备。

#### 3.2.5 FIFA 特性与技能系统（Traits & Skills）
- **能力点消耗与升级**：页面顶部展示球员可用能力点余额，支持消耗能力点解锁与提升特性（Traits）及技能（Skills）等级。

#### 3.2.6 群相册与基础管理模块（继承）
- **相册管理**：支持相册创建、照片批量上传、大图预览及删除。
- **分队与MVP榜单**：支持分队卡片与中文位置筛选，MVP榜单按单场MVP累计次数降序排列。

## 4. 业务规则与核心逻辑

1. **活动报名与满员规则**：
   - 当已报名人数 < 活动人数上限：队员可正常点击报名并成功加入正选名单。
   - 当已报名人数 >= 活动人数上限：报名通道立即关闭，状态置为「已满员」，禁用报名操作，不提供任何候补入口。
2. **活动退出与费用规则**：
   - 距开赛时间 >= 4小时：队员取消报名成功，释放正选名额（其他队员可重新报名），不产生分摊责任。
   - 距开赛时间 < 4小时：队员取消报名需正常承担AA分摊费用，或自行寻找替补顶替。
3. **评分排名计算规则**：
   - 评分中心按照球员综合评分从高到低进行降序排列并生成连续排名序号（1, 2, 3...）。同分情况下按系统既定辅助维度或并列规则展示排名。
4. **装备回收规则**：
   - 出售回收价严格等于购买原价（100%返还），出售成功后背包扣除装备，即时返还对应代币。
5. **能力点流转规则**：
   - 球员基础属性、FIFA特性与技能共用同一能力点池，解锁/升级不可逆，扣点后即时生效。

## 5. 异常与边界情况

| 序号 | 异常/边界场景 | 处理规则 |
| :--- | :--- | :--- |
| 1 | 活动达到上限人数时队员点击报名 | 按钮置灰并显示「已满员」，点击提示「当前活动已满员，无法报名」 |
| 2 | 两名队员在最后一个名额时同时提交报名 | 依据服务端接收先后顺序，首位成功报名，次位提示「手慢了，活动已满员」并刷新状态 |
| 3 | 球员暂无评分数据时进入评分中心 | 评分列表中该球员评分为「暂无」或「-」，排名展示在已评分球员之后或标记为「未上榜」 |
| 4 | 队员在开赛前不足4小时尝试取消报名 | 弹窗明确提示「距开赛不足4小时取消仍需正常AA分摊费用，请确认是否继续取消或寻找替补」 |
| 5 | 页面在小屏或超长屏设备上滑动 | 单层列表平滑滚动，底部悬浮操作按钮在滑动过程中自动隐藏，停滞或到达边界时恢复展示 |

## 6. 验收标准

1. 进入活动报名页面，页面宽度自适应不同屏幕尺寸，页面仅存在单层滚动条，无内外部嵌套双滚动条问题。
2. 在活动报名页面滑动列表时，底部的报名操作按钮在滑动过程中平滑隐藏，停止滑动后重新展示。
3. 活动报名人数达到设定上限后，页面明确显示「已满员」，不再出现任何候补（waiting list）选项或排队提示，无法继续报名。
4. 进入评分中心页面，球员列表中每位球员均清晰展示其对应的评分数值以及对应的评分排名序号。
5. 活动详情页正确展示「开赛4小时前退出接龙可免分摊费用」的退费规则公告。
6. 队长进入图床设置页，已用储存量以正确的 KB 单位展示，总容量正确显示对应规格（如 10GB）。
7. 装备背包中的「原价出售」功能正常生效，100%返还购买代币；FIFA特性与技能页可正常使用能力点完成解锁与升级。

4. 图床自动扩容与第三方云存储多源切换功能。
